## 回填規則（按步驟執行）

### 1. 輸入完整性與工作副本

1. 讀取單一上傳活頁簿，不修改原檔；確認 `Cover` 及五張必要 Sheet 和上述欄位存在。
2. 缺任一必要 Sheet 時列出所有缺少名稱後立即停止，不回填、不留下部分輸出、不提供下載。
3. 期間由 Cover B2 取得；本測試值為 202610，上一月為 202609。先複製原工作簿作工作副本，保留 Sheet、公式、格式、合併範圍及非目標儲存格。
4. Cover 目標列及 PC 欄依欄名／Code 標籤定位；列號用於本 202610 golden 驗收，程式亦應驗證其標籤，不能只依固定座標盲寫。

### 2. 材料分析：Cover 第 10–20 列

1. 忽略 BD `Reason` 包含 `Material QV=0` 的資料。
2. 從 Reason 開頭取整數 Code，以 Cover Reason Code 1–11 配對第 10–20 列；按 N PC 分組加總 BB 金額，寫入對應 PC 欄。
3. 未知／空白 Code 或 PC 不得猜測歸類；將原始值、金額及來源列記入追溯，計入警告。
4. 第 8 列 Sampling Amount 按 PC 加總可識別且未排除的材料分類金額；未分類／無效資料僅列追溯，不併入已識別分類及抽樣金額。第 9 列 Sampling Ratio = 第 8 列 ÷（第 23 列 Sub-total − 第 21 列報工差異）。抽樣金額為 0 時，原模板 IF 公式回傳 0；分母為 0 且抽樣金額非 0 時，明確回報公式計算失敗，不覆寫公式或提供錯誤報表。

### 3. 生產工單：Cover 第 21–23 列

1. 按 BY PC 加總 BS `QV in MOH (LC)`，填第 21 列 Code 12。
2. 按 BY PC 加總 R `QV Amt (LC Currency)`；每個 PC 的第 22 列 Code 13 = 該 PC R 總額 − 該 PC 第 10–20 列總額 − 該 PC 第 21 列。
3. 第 23 列 Sub-total = 第 10–22 列加總；逐 PC 必須等於該 PC 生產工單 R 總額。

### 4. 會計調整：按 Text 規則分桶

按 D PC、Q 金額、R Text 分組；關鍵字忽略大小寫並採 Contains。每筆只能進一桶，按下列順序 first-match：

| 順序 | Text 條件 | Cover 目標 |
|---|---|---|
| 1 | 包含 `Vendor Paid` | 第 24 列 `Vendor paid` |
| 2 | 包含 `不良報廢` 或 `非生產性工時` | 第 27 列 `Material scrap` |
| 3 | 包含 `QV offset with` | 第 31 列 `Adjust to 65011210-Manual` |
| 4 | 包含 `短裝材料扣款` | 第 54 列 Reason Code 918 |
| 5 | 其餘文字或空白 | 第 28 列 `Other` |

第 29 列 Sub-total = 第 24–28 列。逐 PC 五桶加總必須等於會計調整 Q 金額總額。

短裝關鍵字同時接受 PO 新文字的 `短装材料扣款` 與測試檔中的 `短裝材料扣款`，不改變其他分類優先順序。

### 5. 65011201：Manual／Auto Reserve

按 BY PC、R 金額及 CK Remark 分類：

| 條件 | Cover 目標 |
|---|---|
| Remark 包含 `QV offset with`（忽略大小寫） | 第 30 列 `Adjust to 65011201-Manual` |
| Remark 開頭前 6 個數字等於 202610 `current_period` | 第 35 列 `Current QV Auto reservation` |
| Remark 開頭前 6 個數字等於 202609 `previous_period` | 第 34 列 `Preivous QV Auto reverse` |

目前 PO 規則未要求 Auto 分類另外包含 `QV/PV/STD Change Reserve` 字樣；因此實算按日期前綴規則會把 `202610 QV/PV/STD Change Adjustment` 也納入。此點與人工標準答案相衝突，詳見「Golden 差異」，不可自行增加舊版文字篩選。第 36 列 Sub-total = 第 30–35 列。

### 6. 庫存調整：Reason Code × PC，累加寫入

1. K 金額按 S PC 與 O Reason Code 分組；Code 標準化為文字、去空格及小數點後完全比對。
2. 來源 Code 938 或 944 一律對 Cover 第 65 列 `938&944`；其他 Code 對應 Cover 同 Code 列。
3. 庫存值必須加到目標儲存格既有值，不得覆蓋；Code 918 因第 4 步可能已有會計短裝金額，必須將兩來源累加。
4. 未識別 Code／PC 列入追溯與警告，不得寫入猜測列。第 78 列 Sub-total = 第 37–77 列。

### 7. 小計、Total、追溯與交付

| Cover 列 | 計算 |
|---|---|
| 23 | 第 10–22 列 |
| 29 | 第 24–28 列 |
| 36 | 第 30–35 列 |
| 78 | 第 37–77 列 |
| 79 Total | 第 23、29、36、78 列四個 Sub-total 加總 |
| 80 | Cover 原有 `未返還的local consign parts` 金額；本輸入值為 0 |
| 81 Total QV Return | 第 79 列 + 第 80 列 |

Cover 上既有公式保留；第 8、9 列及 Total 欄已有公式時不得以靜態值覆寫。程式使用 Decimal 計算並更新公式的 OOXML 快取值，下載後不必先手動開 Excel 才能比對金額。僅支援本 Cover 所使用的算術、SUM、IF 公式；無法計算／與指定回填規則不相符的公式明確報錯。金額驗收以分（0.01）為單位，差異容許值 0；比率採 1e-12 浮點讀值誤差。

同一輸出活頁簿新增 `金額追溯明細` Sheet，逐筆記錄來源檔／Sheet／列號、原始與標準化 PC、原始分類值、分類規則／期間條件、金額欄、Cover 目標格、回填前值／本次金額／回填後值、狀態及異常原因。空白／未定義資料保留在追溯，不併入已定義 PC。

每張來源 Sheet 的有效資料逐筆保留（包含忽略和異常列）；生產工單同列保留 R 總額與 BS MOH 金額，另外逐 PC 產出 Code 13 倒減計算列。回填前／本步加總／回填後欄位表示該來源步驟對目標格的彙總變動，不能把重複出現在各來源列的「本步加總」再次相加。原始字串以純文字寫入追溯，避免被當成 Excel 公式。

本機驗證不實際寄送 Email／Teams；本次回覆只涵蓋回填成功、失敗或警告、下載結果及追溯。正式通知另依部署授權與通知流程處理。

2026-11-16 再次逐列比對正常輸入與人工答案中的五張來源表：本文件欄位契約內的 PC／金額／分類（包含生產工單 MOH）全部相同，欄位值差異數均為 0。因此差異不是來源檔版本不同，而是 Cover 人工分類／篩選口徑與新規則不同；Code 7／10 的重分類依據仍無法由同一批來源推得。

兩個非金額差異是 Cover C32、C34：人工答案將 `Previous` 拼成 `Preivous`。此外輸入 Cover E8 原有 `=SUM(E10:E20)` 公式，人工答案將其改為常數 431,668.71。故金額以 golden 作值比對；公式、標籤、樣式、合併儲存格與非目標欄位必須以原始輸入作保護基準，不可照抄 golden 的這三項非金額編輯。

**阻擋正常案例通過的必要規則決策：**
1. Reason Code 7／10：確認是否另有 1,907.90 的調整／重分類條件；若沒有，需修正人工答案為依來源 Code 匯總的值。
2. 65011201 Auto：確認採 PO 新規則（僅 YYYYMM 前綴，包含 Adjustment）並更新 golden；或明確把 `QV/PV/STD Change Reserve` 作為必要條件，讓規則與現有 golden 相符。Sprint 2 不可暗中沿用未列入新規則的舊篩選。

在以上兩項決策完成及人工答案更新／確認前，正常情境狀態固定為 **FAIL / 規格與 golden 不一致**；不得因總額相抵或部分小計正確而顯示「回填成功」。

## 本機驗收工作流

1. **固定資料版本**：記錄本次使用的 202610 檔名；勿直接修改已納入版本控制的原始 fixture。每次執行先複製到獨立工作目錄。
2. **缺表情境**：先執行情境二，確認明確回報缺少 `會計調整`，未產生部分檔案。
3. **異常 PC 情境**：情境三應報告材料分析 26,188 筆 PC 空白；其他可識別來源可繼續完成回填；空白 PC 金額不得併入已定義 PC，且要逐筆追溯。
4. **正常情境**：運行正常輸入；驗證每一來源分類金額、四個 Sub-total、row 79／81、抽樣公式與追溯均符合規則。
5. **Golden 比對**：先檢查「Golden 差異」兩項決策已解決，再比對 E:H 金額／比率格（以分為金額單位，金額差異容許值 0）。標籤／格式／公式／合併範圍與原始輸入比較，不以人工答案作其基準。
6. **完成條件**：缺表 case 正確硬停、異常 PC case 可識別資料回填並告警、Golden 差異為 0、公式與格式保留、追溯明細產出；否則驗收未完成。
